# Сложная форма компании — Next.js + Ant Design

## Запуск

Из корня репозитория:

```sh
npm ci
npm run prepare:examples
cd examples/nextjs
npm ci
npm run dev
```

Откройте http://localhost:3000. Если пример уже установлен, достаточно `npm run dev` в этой папке.

Проверки: `npm run typecheck`, `npm test`, `npm run build`. Production: `npm run build && npm start`.

## Что есть в форме

- 59 начальных полей: реквизиты, адрес головного офиса, комментарий, числа, checkbox и multiple select.
- `contacts[].phones[]`: контакты с редактируемыми списками телефонов.
- `branches[].departments[].members[]`: филиалы, отделы и сотрудники, три уровня массивов.
- Добавление/удаление на каждом уровне, перестановки, копирование целого филиала со всеми отделами и сотрудниками.
- Страны, зависимые города, отрасли и поиск сотрудников: локальные Promise с задержкой 400–1200 мс.
- Разная задержка городов позволяет быстро менять страны и проверять защиту от устаревшего ответа.
- Поиск сотрудника по слову «ошибка» намеренно возвращает отказ. Измените поисковый запрос, чтобы восстановить загрузку.
- Условные реквизиты юрлица/ИП, уведомления и согласование. Скрытие сохраняет значения согласно `shouldUnregister: false`.
- Required/pattern/min/max и проверка общего бюджета; пустые массивы не проходят required-проверку.
- Асинхронная отправка с блокировкой формы и снимком результата.
- Черновик в localStorage через опубликованный persistence/local, ключ `form-builder-complex-application-v1`.

## Что попробовать

1. Измените название. Во вкладке values появится новое значение, в dirty — изменённый путь, после blur он появится в touched.
2. Добавьте контакт, несколько телефонов, филиал, отдел и сотрудников. Посмотрите вложенную JSON-структуру.
3. Измените данные первого филиала, переместите его вниз, затем добавьте сотрудника в его отдел. Вложенные значения остаются у своего филиала.
4. Смените страну: город очистится. Пока справочник загружается, другие поля остаются доступны.
5. Поищите «Анна» в сотрудниках. Затем «ошибка» и другой запрос. Старые ответы не заменяют результаты нового запроса.
6. Отключите уведомления и включите снова: email сохранится. Аналогично работает согласование.
7. Нажмите «Показать серверную ошибку», затем «Очистить ошибки» и «Проверить все поля».
8. Уменьшите годовой бюджет ниже суммы бюджетов филиалов и проверьте форму.
9. Сделайте «Снимок getValues», затем измените поля: снимок остаётся прежним, values обновляются.
10. Подтвердите данные и отправьте заявку. Ниже появится неизменяемый JSON результата. Успешная отправка удаляет сохранённый черновик.
11. Измените данные, подождите сохранения черновика и перезагрузите страницу.

## Панель управления

- «Загрузить демоданные»: `reset(createDemoValues())`, делает пример новой исходной версией.
- «Очистить форму»: `reset(createEmptyValues())`, включая пустые массивы.
- «Сбросить изменения»: `reset()`, возвращает последнюю исходную версию; после очистки это пустая форма.
- «Принять как исходные»: `reset(getValues())`, сохраняет данные и сбрасывает dirty.
- «Изменить через setValue»: меняет название и вложенный адрес с shouldDirty/shouldTouch.
- «Сбросить одно поле»: `resetField('company.name')`.
- «Проверить все поля»: `trigger(undefined, { shouldFocus: true })`.
- Серверная ошибка и очистка: `setError` / `clearErrors`. `clearErrors` сам по себе не пересчитывает isValid.
- «Снимок getValues»: однократное чтение, отдельное от live useWatch.
- «Удалить черновик»: удаляет сохранённую копию, не меняет текущие значения формы. Последующее редактирование может создать новый черновик.

## Как устроен код

- `app/model.ts` — модель данных и фабрики свежих default values.
- `app/fields.ts` — типизированная конфигурация листовых полей и правил RHF.
- `app/array-fields.tsx` — нативные useFieldArray, стабильные RHF id, вложенные компоненты.
- `app/mock-api.ts` — Promise вместо настоящего сервера.
- `app/use-options.ts` — загрузка, ошибка, retry и игнорирование устаревших ответов.
- `app/remote-fields.tsx` — зависимые селекты и поиск сотрудников.
- `app/inspector.tsx` — инструменты управления, подписки на значения/состояние и безопасный JSON ошибок без DOM refs.
- `app/kit.tsx` — Ant Design adapter, textarea/number и AsyncSelect.
- `app/ApplicationForm.tsx` — один useForm, persistence, условные секции и submit.

### Важные детали массивов

Вся форма использует один RHF instance. Дочерние компоненты получают его через useFormContext. `useFieldArray` не поддерживает динамическую смену name, поэтому компонент вложенного hook перемонтируется ключом, когда меняется путь родителя. `shouldUnregister: false` сохраняет данные при этом remount.

После синхронных append/remove/move/insert вызывается сигнал `refreshStructure`: он заставляет родителя немедленно перестроить реестр FormBuilder из `getValues()`, до следующего рендера дочернего массива. Это только сигнал рендера, а не копия состояния формы. Иначе уведомление useWatch от useFieldArray может прийти слишком поздно и новый Slot ещё не будет найден в реестре.

Для статических форм подходит defineFields и точная типизация Slot.name. Здесь состав полей динамический: конфигурация проверяется через `FieldConfig<ApplicationValues, typeof adapter.fields>`, а слоты находят текущий индексированный путь runtime.

### UI loading и RHF disabled

`AsyncSelect` принимает `uiDisabled`, которое блокирует только компонент. Не используйте RHF `disabled` для загрузки справочника: RHF исключает такие значения из submit. Общее восстановление/submit блокирует всю форму через FormBuilder loading без изменения RHF state.

Ant Design 5 использует официальный `@ant-design/v5-patch-for-react-19` для совместимости интерактивных эффектов с React 19.
